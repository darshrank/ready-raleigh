# Decisions

One line each. Newest at the bottom. Do not reopen a decision without writing why.

- Core game runs in the browser from static files; server features are optional layers.
- Analysis unit is H3 resolution 9; cells referenced by integer index.
- Shelters snap to real OSM candidate sites; coverage precomputed per site (dry and flooded).
- Flood model uses FEMA flood zones as 3 steps; simplified on purpose, disclosed in the pitch.
- Runtime is TypeScript (app, server, shared); Python only for the offline data pipeline.
- Scoring and optimizer live in shared/ so the browser and the optimizer use the same math.
- Solana uses @solana/web3.js v1 on devnet only; play money, never real money.
- Repo layout: docs live in docs/. Claude's checkout is wolfhacks/claude (main); Codex's worktree is wolfhacks/codex (branch data-pipeline).
- Deps (P1): app uses react 18, maplibre-gl, @deck.gl/{core,layers,geo-layers,mapbox}, h3-js, zustand, motion, tailwindcss v4 via @tailwindcss/vite; server uses fastify + ws (raw ws on the upgrade event, no plugin); shared uses h3-js; root dev tools are typescript, vitest, tsx, concurrently.
- maplibre-gl pinned to ^5: v6 removed map.transform, which @deck.gl/mapbox 9.4 still reads (crash in getViewport). Revisit when deck.gl supports v6.
- Data path is set by VITE_DATA_BASE (default /data/fixtures). Set it to /data once the pipeline writes the real files.
- Fixtures are generated by `npm run fixtures` (shared/scripts/make-fixtures.ts), not hand-edited, so coverage, cutOff and unlocks stay consistent.
- Routing: a 40-line history-API router in app/src/router.tsx instead of a dependency (five static routes).
- Basemap: our own MapLibre style on OpenFreeMap's OpenMapTiles source (no sprite), not a restyled positron, so only DESIGN.md layers exist.
- Halftone dots come from the pipeline's flood_dots.json (`FloodDot = [lon, lat, step]`); the browser no longer rasterises flood polygons (that froze /solo for ~30 s). make-fixtures writes a fixture flood_dots.json. Replaces the in-browser stand-in.
- Map first (user request, after P5): top-down camera with an optional Tilt; no hex extrusion or grid; population is an opt-in flat ink fill at most 30%. Replaces the extruded vulnerable-share hexes.
- Camera framing fits cells and sites, not flood polygons, so phones open at zoom 13 or more where street names and buildings exist.
- Engine (P4), flood: each at-risk cell's weight splits into a car part (protected by a usable shelter's coverFlood or a protected road's unlocks) and a no-car part, 2.5 * noCarHH (protected by a bus pickup within gridDisk 2). People and vulnerable counts follow the protected share of the cell's weight.
- Engine (P4), heat: cooling center credit 1, water station 0.5 (HEAT_COVER_CREDIT in config), trees stack and fully protect a cell cooled below the threshold; coverage keeps the best credit, so adding a placement never lowers the score.
- score() and simTimeline() throw PlanError for invalid plans (over budget, wrong-mode type, unknown or repeated site/road, bad cell). Cost comes from the placements; plan.spent is not trusted.
- The engine caches a typed-array index per bundle object (WeakMap). Treat a loaded DataBundle as immutable.
- Optimizer: CELF lazy greedy, best of gain-per-dollar greedy, pure-gain greedy and best single placement. Writes optimal_<mode>.json as OptimalPlan {mode, built, budget, plan, score}.
- Timeline: cut-off cells join the counts at the final step. A protected road does not extend a shelter's precomputed coverFlood.
- Fixtures: added a dry shelter site south of Rocky Branch (Avent Ferry Road Church) so a usable shelter can reach the cut-off side.
- P3 data pipeline uses OSMnx 2.1.1, NetworkX 3.6.1, and SciPy 1.17.1 for the requested directed road graph, sparse routing, and multiprocessing coverage calculations.
- Shelter coverage (user decision, after real data landed): a flooded cell counts as covered by a usable shelter if it is in the site's coverDry (residents evacuate before the water arrives); a cut-off cell that does not flood needs coverFlood. Shelters that flood stay unusable. Replaces coverFlood-only coverage (P4). See shelterCells() in shared/src/engine/coverage.ts.
- P6 planning: state in a zustand store (app/src/plan/store.ts); counters come from the engine (`score().protectedPeople`, `planCost`). The store refuses over-budget placements and a second piece on one site or road, so score() never sees an invalid plan.
- P6 snapping is in screen pixels: a shelter snaps to the nearest site within 36 px (48 touch), a road to the nearest flood road within 16 px (26 touch), a bus pickup takes the H3 cell under the point. Flooded sites can take a shelter; it covers nobody and the status line says so.
- P6 input: capture-phase pointer handlers on the map container. A press on a placed piece is kept from MapLibre and deck.gl and drags the piece; any other press passes through, so the map still pans while a piece is armed. MapLibre's arrow-key panning is off on /solo; arrows drive the cell cursor (about 24 px per press at any zoom).
- Site squares are 160 m wide, clamped to 5-14 px (9-18 px while placing a shelter), so the city-wide opening view shows specks instead of a blob. Hospital names show from zoom 10.5; the Facilities toggle hides hospitals and sites (sites still show while placing a shelter).
- The planning clock starts when the data is on screen; at 0:00 planning ends as if "Start the storm" was pressed. The storm phase is a placeholder until P7.
- P7 dependency: app declares @deck.gl/extensions ^9.4.0 (PathStyleExtension, for dashed closing roads). Already installed under @deck.gl/geo-layers at the same version; nothing new downloaded.
- P7 animation: MapView takes `frameLayers(now)`; while set, a requestAnimationFrame loop calls overlay.setProps outside React, so the storm never re-renders the page per frame. Resident positions and colors go to deck.gl as double-buffered binary attributes (deck.gl skips an upload when it sees the same array twice).
- P7 residents: systematic sample of the at-risk weighted people, 1 dot per 25 (max 6,000; real data gives 5,999 at ~36.7 per dot). Each dot is car or no-car part; covered car dots go to the nearest covering shelter, else stay home safe if a protected road unlocks the cell; covered no-car dots walk to the nearest covering bus pickup; the rest are stranded. Coverage comes from the engine (planState, placementEffect), counters from simTimeline. A cell meets the water at its flood step; cut-off-only cells at the final step, like simTimeline.
- P7 pacing: band slides in, step 1 at 0.8 s, then a step every 4 s; dots grow 600 ms; closing roads dashed for 1.8 s; storm ends at 12.8 s and the results card shows. Pass 1 travel is straight lines (no road routing).
- P7: the storm's new layer types (TripsLayer, dashed PathLayer) are mounted hidden during planning so their shaders compile early; without it the storm's first frame stalled ~600 ms.
- deck.gl cannot re-initialize a layer instance it dropped, so /solo's planning stack is cloned each time it is built (props unchanged, deck.gl updates nothing). Coming back from the storm otherwise threw assertions.
- Visual overhaul (user request, after P7): two moods, day board and night storm; DESIGN.md rewritten first. Replaces the side rail with floating HUD plates and the flood halftone with realistic water. Halftone stays for heat.
- Flood water is native MapLibre layers in the basemap style (map/flood.ts, inserted above streets and buildings, below every label), not deck.gl dots. The app loads flood_steps.geojson again (553 KB) and no longer loads flood_dots.json.
- Water animation only touches cheap paths: constant paint values (color, shimmer, opacities), feature-state (per-part growth, quantized to twelfths) and visibility. Data-driven or cross-faded paint changes (line-dasharray) relayout the source, so the flowing dash is 4 phase-shifted dash layers crossfaded by opacity.
- Streets under water come from the vector tiles (querySourceFeatures), clipped against a 15 m raster of the flood steps built in idle time. roads_graph.json edges are straight chords (up to 4.7 km) and do not follow the street; the engine still uses the graph for closures.
- Night palette is a second palette over the same basemap layers (basemap.ts palette/applyPalette), with storm tokens in styles.css. Switched by paint updates with per-property transitions (0 ms under the wipe, 1.6 s for the clear).
- Storm pacing (storm/sim.ts): wipe 0.7 s, tilt to 55 degrees, then per step: water grows 1.5 s, the helicopter flies 1.5 s, holds 2 s with a LIVE caption, pulls back 1.5 s; storm 23 s, clears 1.6 s, results 1.4 s later. "Skip to results" moves the storm clock to the end.
- Sound is synthesized with Web Audio (ui/sound.ts: stamp, alert chime, rain, thunder), no files and no dependency. On by default on desktop, off on phones (coarse pointer), remembered in localStorage.
- @deck.gl/extensions is no longer imported (no dashed deck.gl roads); still declared in app/package.json, safe to remove.
- /solo starts at the title on every visit (store.restart on mount); /solo?skip opens straight on the planning board for scripts.
