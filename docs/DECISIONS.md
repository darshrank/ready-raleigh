# Decisions

One line each. Newest at the bottom. Do not reopen a decision without writing why.

- Core game runs in the browser from static files; server features are optional layers.
- Analysis unit is H3 resolution 9; cells referenced by integer index.
- Shelters snap to real OSM candidate sites; coverage precomputed per site (dry and flooded).
- Flood model uses FEMA flood zones as 3 steps; simplified on purpose, disclosed in the pitch.
- Runtime is TypeScript (app, server, shared); Python only for the offline data pipeline.
- Scoring and optimizer live in shared/ so the browser and the optimizer use the same math.
- Solana uses @solana/web3.js v1 on devnet only; play money, never real money.
- Repo layout: docs live in docs/. Claude's checkout is wolfhacks/claude (main); Codex's worktree is wolfhacks/codex (branch data-pipeline).
- Deps (P1): app uses react 18, maplibre-gl, @deck.gl/{core,layers,geo-layers,mapbox}, h3-js, zustand, motion, tailwindcss v4 via @tailwindcss/vite; server uses fastify + ws (raw ws on the upgrade event, no plugin); shared uses h3-js; root dev tools are typescript, vitest, tsx, concurrently.
- maplibre-gl pinned to ^5: v6 removed map.transform, which @deck.gl/mapbox 9.4 still reads (crash in getViewport). Revisit when deck.gl supports v6.
- Data path is set by VITE_DATA_BASE (default /data/fixtures). Set it to /data once the pipeline writes the real files.
  Superseded: the default is now /data (real data) for the app, the server and `npm run optimize`; set VITE_DATA_BASE=/data/fixtures for the small test set.
- Fixtures are generated by `npm run fixtures` (shared/scripts/make-fixtures.ts), not hand-edited, so coverage, cutOff and unlocks stay consistent.
- Routing: a 40-line history-API router in app/src/router.tsx instead of a dependency (five static routes).
- Basemap: our own MapLibre style on OpenFreeMap's OpenMapTiles source (no sprite), not a restyled positron, so only DESIGN.md layers exist.
- Halftone dots come from the pipeline's flood_dots.json (`FloodDot = [lon, lat, step]`); the browser no longer rasterises flood polygons (that froze /solo for ~30 s). make-fixtures writes a fixture flood_dots.json. Replaces the in-browser stand-in.
- Map first (user request, after P5): top-down camera with an optional Tilt; no hex extrusion or grid; population is an opt-in flat ink fill at most 30%. Replaces the extruded vulnerable-share hexes.
- Camera framing fits cells and sites, not flood polygons, so phones open at zoom 13 or more where street names and buildings exist.
- Engine (P4), flood: each at-risk cell's weight splits into a car part (protected by a usable shelter's coverFlood or a protected road's unlocks) and a no-car part, 2.5 * noCarHH (protected by a bus pickup within gridDisk 2). People and vulnerable counts follow the protected share of the cell's weight.
- Engine (P4), heat: cooling center credit 1, water station 0.5 (HEAT_COVER_CREDIT in config), trees stack and fully protect a cell cooled below the threshold; coverage keeps the best credit, so adding a placement never lowers the score.
- score() and simTimeline() throw PlanError for invalid plans (over budget, wrong-mode type, unknown or repeated site/road, bad cell). Cost comes from the placements; plan.spent is not trusted.
- The engine caches a typed-array index per bundle object (WeakMap). Treat a loaded DataBundle as immutable.
- Optimizer: CELF lazy greedy, best of gain-per-dollar greedy, pure-gain greedy and best single placement. Writes optimal_<mode>.json as OptimalPlan {mode, built, budget, plan, score}.
- Timeline: cut-off cells join the counts at the final step. A protected road does not extend a shelter's precomputed coverFlood.
- Fixtures: added a dry shelter site south of Rocky Branch (Avent Ferry Road Church) so a usable shelter can reach the cut-off side.
- P3 data pipeline uses OSMnx 2.1.1, NetworkX 3.6.1, and SciPy 1.17.1 for the requested directed road graph, sparse routing, and multiprocessing coverage calculations.
- Shelter coverage (user decision, after real data landed): a flooded cell counts as covered by a usable shelter if it is in the site's coverDry (residents evacuate before the water arrives); a cut-off cell that does not flood needs coverFlood. Shelters that flood stay unusable. Replaces coverFlood-only coverage (P4). See shelterCells() in shared/src/engine/coverage.ts.
- P6 planning: state in a zustand store (app/src/plan/store.ts); counters come from the engine (`score().protectedPeople`, `planCost`). The store refuses over-budget placements and a second piece on one site or road, so score() never sees an invalid plan.
- P6 snapping is in screen pixels: a shelter snaps to the nearest site within 36 px (48 touch), a road to the nearest flood road within 16 px (26 touch), a bus pickup takes the H3 cell under the point. Flooded sites can take a shelter; it covers nobody and the status line says so.
- P6 input: capture-phase pointer handlers on the map container. A press on a placed piece is kept from MapLibre and deck.gl and drags the piece; any other press passes through, so the map still pans while a piece is armed. MapLibre's arrow-key panning is off on /solo; arrows drive the cell cursor (about 24 px per press at any zoom).
- Site squares are 160 m wide, clamped to 5-14 px (9-18 px while placing a shelter), so the city-wide opening view shows specks instead of a blob. Hospital names show from zoom 10.5; the Facilities toggle hides hospitals and sites (sites still show while placing a shelter).
- The planning clock starts when the data is on screen; at 0:00 planning ends as if "Start the storm" was pressed. The storm phase is a placeholder until P7.
- P7 dependency: app declares @deck.gl/extensions ^9.4.0 (PathStyleExtension, for dashed closing roads). Already installed under @deck.gl/geo-layers at the same version; nothing new downloaded.
- P7 animation: MapView takes `frameLayers(now)`; while set, a requestAnimationFrame loop calls overlay.setProps outside React, so the storm never re-renders the page per frame. Resident positions and colors go to deck.gl as double-buffered binary attributes (deck.gl skips an upload when it sees the same array twice).
- P7 residents: systematic sample of the at-risk weighted people, 1 dot per 25 (max 6,000; real data gives 5,999 at ~36.7 per dot). Each dot is car or no-car part; covered car dots go to the nearest covering shelter, else stay home safe if a protected road unlocks the cell; covered no-car dots walk to the nearest covering bus pickup; the rest are stranded. Coverage comes from the engine (planState, placementEffect), counters from simTimeline. A cell meets the water at its flood step; cut-off-only cells at the final step, like simTimeline.
- P7 pacing: band slides in, step 1 at 0.8 s, then a step every 4 s; dots grow 600 ms; closing roads dashed for 1.8 s; storm ends at 12.8 s and the results card shows. Pass 1 travel is straight lines (no road routing).
- P7: the storm's new layer types (TripsLayer, dashed PathLayer) are mounted hidden during planning so their shaders compile early; without it the storm's first frame stalled ~600 ms.
- deck.gl cannot re-initialize a layer instance it dropped, so /solo's planning stack is cloned each time it is built (props unchanged, deck.gl updates nothing). Coming back from the storm otherwise threw assertions.
- Visual overhaul (user request, after P7): two moods, day board and night storm; DESIGN.md rewritten first. Replaces the side rail with floating HUD plates and the flood halftone with realistic water. Halftone stays for heat.
- Flood water is native MapLibre layers in the basemap style (map/flood.ts, inserted above streets and buildings, below every label), not deck.gl dots. The app loads flood_steps.geojson again (553 KB) and no longer loads flood_dots.json.
- Water animation only touches cheap paths: constant paint values (color, shimmer, opacities), feature-state (per-part growth, quantized to twelfths) and visibility. Data-driven or cross-faded paint changes (line-dasharray) relayout the source, so the flowing dash is 4 phase-shifted dash layers crossfaded by opacity.
- Streets under water come from the vector tiles (querySourceFeatures), clipped against a 15 m raster of the flood steps built in idle time. roads_graph.json edges are straight chords (up to 4.7 km) and do not follow the street; the engine still uses the graph for closures.
- Night palette is a second palette over the same basemap layers (basemap.ts palette/applyPalette), with storm tokens in styles.css. Switched by paint updates with per-property transitions (0 ms under the wipe, 1.6 s for the clear).
- Storm pacing (storm/sim.ts): wipe 0.7 s, tilt to 55 degrees, then per step: water grows 1.5 s, the helicopter flies 1.5 s, holds 2 s with a LIVE caption, pulls back 1.5 s; storm 23 s, clears 1.6 s, results 1.4 s later. "Skip to results" moves the storm clock to the end.
- Sound is synthesized with Web Audio (ui/sound.ts: stamp, alert chime, rain, thunder), no files and no dependency. On by default on desktop, off on phones (coarse pointer), remembered in localStorage.
- @deck.gl/extensions is no longer imported (no dashed deck.gl roads); still declared in app/package.json, safe to remove.
- /solo starts at the title on every visit (store.restart on mount); /solo?skip opens straight on the planning board for scripts.

- Flood realism (2026-10-03, lanes A/B): assume OSM edges tagged as bridges remain passable at every flood step; `bridge=no/false/0` is not a bridge. This deliberately ignores actual deck elevation/overtopping. Preserve bridge/ref tags on download and rebuild a cache missing bridge tags. The current cache contains 670 tagged directed bridge edges.
- Cell contract change: required `floodFrac: number` is the fraction of the full H3 polygon inside the **cumulative** step-3 hazard union (0..1); `floodStep` is the first cumulative area share >=20%, otherwise null. Compute all three shares using unsimplified FEMA geometry in EPSG:26917, union overlapping zones once, assume uniform population inside each cell, and save per-step shares in `pipeline/out/cell_flood_shares.json`.
- Flood exposure: cells meeting the flood threshold contribute `weightedPeople * floodFrac` and `pop * floodFrac`; a dry/sub-threshold cell that is cut off contributes its full weight/population. A flooded cell that is also cut off uses the flooded fraction once. `cutOff` now means a previously available dry hospital route is lost; 16 pre-existing dry disconnections are excluded and remain in metadata. This replaces P3's final-state-only interpretation.
- Site contract change: `coverDry` and `coverFlood` contain only at-risk cell indices, sorted by drive time (ties by cell index); new required `driveDry` and `driveFlood` arrays contain aligned integer **milliseconds**. Actual times, rather than per-site ranks, enable nearest-shelter comparisons. JSON stays compact with integer arrays; filtering irrelevant cells retains all 216 sites in 2,311,270 bytes.
- Shelter capacity is 10,000 actual people, using score's existing people-to-weight conversion for the car part. Allocate globally in ascending drive time, then site ID/cell index; each car part belongs to one shelter with room. The last cell may be partially served; its remainder stays stranded, with no split across shelters. Roads protect their car parts first, freeing shelter seats; buses serve no-car parts independently. Flooded cells use dry evacuation routes, dry cut-off cells use final-step routes, and flooded buildings remain unusable.
- Flood optimizer now recomputes candidate marginal gains every round: capacity reassignment invalidates CELF's stale bounds. Keep the best of gain-per-dollar, pure-gain and a single placement. It is a heuristic baseline, not a proof of the global optimum. `score(plan, data, budget = BUDGET)` adds required `bestPossible`, equal to this optimizer's percentage for the same bundle/mode/budget (not plan.spent). Cache by immutable bundle/mode/budget; the first score computes the baseline.
- `protectorOf(plan, data)` returns `Map<cellIndex, ProtectionSource[]>`; each source has `{placement, part: 'car'|'noCar', share, weighted}`. It uses the same capacity allocation as scoring. A cell can have separate car and no-car protectors, and partial shelter credit; clients must use these shares rather than treating reachability as protection. Non-shelter ties are deterministic by placement ID; heat sources attribute marginal contributions in that order.
- `simTimeline` adds cumulative `protectedWeighted` and `strandedWeighted` per step, alongside people totals. A flooded cell's final affected fraction joins at its first >=20% step; dry cut-off exposure joins at step 3. This preserves the existing discrete cell-entry animation model; it is not a hydraulic time series. Final weighted and people totals equal score().
- Lane boundary for this task: stage the real rebuilt bundle and optimizer result in `pipeline/out/data/`, and updated synthetic fixtures in `shared/fixtures/`. `PIPELINE_DATA_DIR` overrides Python output; `DATA_DIR` selects CLI data. The UI owner adopts the matching data under app/; Codex does not edit app/. Fixtures default to shared/fixtures, with an optional FIXTURES_DIR override. Shared scripts use the existing `node --import tsx` loader; no new dependencies.
- Flood-road labels now use OSM name, then ref, then `Unnamed road near <hood>`; protection rankings use fraction-adjusted exposure. Report resident share against all estimated residents in the Raleigh-plus-1-km study area and report vulnerability-weighted exposure separately. The flood optimizer stops before optimizing if resident exposure exceeds 20%.

- P11 storage (lane D): Tiger Data stores plays only, plus a reference copy of cells/sites/flood_roads for SQL joins. The game keeps reading the static files, so solo mode never needs the database. Tables: `plays`, `placements`, `gauge_readings` (hypertables), continuous aggregates `placements_hourly` and `leaderboard_hourly` with `materialized_only = false` (real-time, a new play counts at once) and a 5-minute refresh policy, view `crowd_by_hood`. Schema in server/src/db/schema.sql, applied idempotently on every server start; reference tables reload when meta.buildDate changes.
- The Tiger database also holds `rounds` and `player_actions` from another branch (feat/ready-raleigh-adit). Our tables use different names and leave those alone.
- server dependencies: `pg` (node-postgres, @types/pg dev) for Tiger Data; `h3-js` (already used by shared/) for spot centers in the planner. sslmode in DATABASE_URL becomes an explicit `ssl` option (certificate verified), which silences node-postgres' sslmode warning.
- POST /api/plays re-scores the plan with the engine and stores the server's score; invalid plans get 400 with the engine's problems. If the data folder cannot be loaded, the client's score is stored as sent. The server reads the same folder as the app (shared/scripts/bundle dataDir: DATA_DIR, else app/public + VITE_DATA_BASE).
- Fail soft: no DATABASE_URL or a failed schema step at start means MemoryStore. At runtime failSoft() saves to memory when a write fails and merges memory into crowd reads.
- GET /api/planner: a spot is a shelter site, a flood road, or a cell. The data's list is the best $10M plan, then up to 10 extra placements from the optimizer at 3x the budget (non-overlapping; the strongest single spots are mostly interchangeable capacity-capped shelters). A crowd spot needs at least 15% of plays (min 1 pick). Walk-in picks within one H3 ring of a data spot count for it; other walk-in picks cluster within one ring. Categories: both, data (the gap), crowd. The 3x optimizer run takes ~6.5 s on real data and is warmed at server start.
- Rooms (P9, user decision): every player is a mayoral candidate; gameplay is the solo game. No central screen: anyone can host from their own device (Among Us style); the host is a player with Start and Next election, passed on if they leave. /host/:code now opens the player page.
- Rooms: the storm starts for everyone at once. "Start the storm" (or 0:00) sends the plan and waits (phase 'waiting'); when every connected candidate is in, or the clock plus LOCK_GRACE_MS (5 s) runs out, the server ranks and every phone starts its storm.
- Rooms: the server is the judge. Locked plans go through buildPlay (same validation and score as POST /api/plays) and are stored with store.savePlay; plays.candidate (nullable text) records the portrait. Rankings: score desc, ties to the earlier lock.
- Rooms run in server memory (room state is short-lived); finished plays are what persist (Tiger Data).
- Candidate art: 16 Open Peeps busts (CC0, Pablo Stanley), recoloured to --ink/--bond at build time by app/scripts/candidates.mjs and inlined so the tokens apply. The source assets are not in the repo.
- app dependency: qrcode (+ @types/qrcode) for the lobby QR, drawn in --ink on --bond.
- P15 live feeds (lane D): USGS Water Services instantaneous values (stage 00065, flow 00060) for every active gauge in the study-area box, NOAA NWPS flood stages (action/minor/moderate/major) matched by USGS id, NWS api.weather.gov latest observations at the nearest station (temperature, rain last hour) and the grid's quantitative precipitation forecast. No keys needed; NWS gets a User-Agent. The box comes from the bundle's cells, so another city only needs its own data folder.
- USGS legacy waterservices.usgs.gov is used because one request gives a box and a period. USGS is moving to api.waterdata.usgs.gov (OGC API, works today); swap parseUsgs/fetchUsgs if the legacy service is retired.
- Live storage: all feeds go to gauge_readings (site_no is the USGS number or 'nws:<station>' / 'nws:<grid>'; parameter stage_ft, flow_cfs, temp_c, rain_mm, rain_forecast_mm), upserted on (site_no, parameter, time) because USGS revises provisional values and forecasts change. Forecast periods are stored at their start time with unit mm/<ISO duration>. New table gauges (flood stages kept when a refresh has none) and real-time continuous aggregate gauge_hourly (avg/min/max/last/count, 15-minute policy).
- Live job: 7-day backfill on start (~75k readings, ~18 s), then every 15 minutes a 3-hour window; NOAA flood stages once a day. Each feed fails on its own and logs. LIVE_FEEDS=false turns the job off. With Tiger, failSoftLive mirrors every write in memory and answers reads from memory if Tiger fails.
- Live summary: trend compares the latest stage with the reading closest to one hour earlier (within 30 min); rising/falling at 0.1 ft. "Below flood stage" uses the minor stage (else moderate, else major). Gauges sort by flood category, then stage as a share of flood stage. Headline is the first fresh gauge (reading under 2 h old) with flood stages. rainNext24hMm sums forecast periods starting from an hour ago to 24 h ahead.

- Semantic zoom (user request, branch sakhi/semantic-zoom): detail layers are MapLibre style layers in `app/src/map/detail.ts`, painted from the basemap Palette (day and storm), each with a minzoom of 14 or more so the city view is unchanged. Icons are signed distance fields drawn on a canvas at load (no sprite), so the palette can swap their color without a relayout. Detail symbols sit below street and place names so those win collisions.
- Places (S1) come from the OpenFreeMap `poi` layer by class/subclass: school, college, hospital (hospital, clinic), place_of_worship, town_hall/community_centre, library/library (library/books is a bookshop), grocery (supermarket, greengrocer, marketplace), fire_station, police. Nursing homes, shops and food are left out.
- Addresses (S2): OpenFreeMap's `building` layer has no name field, so "named buildings" are the named non-commercial `poi` features that are mostly buildings (town_hall townhall/courthouse/public_building, office government/educational_institution, lodging/dormitory, information/office, museum), shown at z16+ with house numbers. No new data file.
- Bus stops (S3): GoRaleigh's public GTFS (https://goraleigh.org/gr_gtfs, feed S1000098, valid 2026-09-06 to 2027-01-31, downloaded 2026-10-03) -> `pipeline/bus_stops.py` (stdlib only; verified TLS with the macOS system CA bundle when Python has none) -> `bus_stops.json` (1,386 boarding stops, 116,584 bytes). Source recorded in meta.json (`sources.busStops`, `busStops`) and credited in the map attribution. Display only: bus pickups still take a cell; the engine is unchanged. The tiles' own bus_stop POIs (all agencies) are not drawn.
- Aerial (S4): NC OneMap Orthoimagery_Latest_cached (Web Mercator tile cache, 6 inch, https://services.nconemap.gov/secure/rest/services/Imagery/Orthoimagery_Latest_cached/ImageServer/tile/{z}/{y}/{x}); checked 2026-10-03: tiles 200 image/jpeg with CORS for the page origin; terms (nconemap.gov/pages/terms) give free and unrestricted use with no release needed, citation NC OneMap / NC CGIA, which the source attribution carries. Raster source minzoom 16, so no tile is requested at the city view. No Google or Esri imagery. applyPalette also re-paints raster saturation/contrast/brightness.
- Site buildings (S5): sites.json ids are 104 osm-node, 100 osm-way, 12 osm-relation, so `pipeline/site_buildings.py` (stdlib + Overpass, answers cached) uses three rules: `contains` (a node inside a building; the smallest if nested), `self` (the site is itself a building), `grounds` (campus or lot: the building at the site point, else the largest building whose center is inside the grounds). No nearest-building guess for nodes outside every footprint: those keep the square. Result 2026-10-03: 162 of 216 matched (contains 50, self 51, grounds 61; nodes 50/104, ways 100/100, relations 12/12), 126,406 bytes. At z15+ the matched site's square hides (useFloodMap, by the store's zoom) and the building is the target; shelter snapping still uses the site point. Card capacity is SHELTER_CAPACITY (same for every site).
- Hex fade (S6): `hexFade(zoom)` (map/layers.ts) scales deck.gl `opacity` of the visible people fill and the hood tint from 1 at z14.5 to 0.35 at z16 (store zoom, quarter steps, so it changes on zoomend only). The invisible pick fill keeps opacity 1. The keyboard cursor and target outlines do not fade (they are targets). Coverage keeps full alpha and gets a 1 px ink rim from z15 (COVERAGE_RIM_ZOOM).

- Evacuation chain (user decision, supersedes the independent-pieces rules above: "Engine (P4), flood" no-car part served by any bus pickup, and roads covering the car part of every unlocked cell). Shelters are the destination; a bus pickup only helps no-car residents of the cells within gridDisk 2 if a placed, usable shelter can be reached from those cells (the site's existing coverDry/coverFlood routes), and its riders take that shelter's seats; with no shelter in reach it scores 0. A protected road saves everyone (both parts) in the dry cut-off cells it unlocks and they need no seat; it no longer helps flooded cells in `unlocks` (they must evacuate). 62 of the 121 unlock references on the real data are flooded cells.
- Seats go to drivers first, then the buses fill what is left, both nearest-first by drive time. This keeps "adding a piece never lowers the score" true (a mixed nearest-first pass let a new pickup push out farther drivers with a higher weight per seat).
- Optimizer: bus pickups are candidates if they reach any no-car at-risk weight (their gain alone is 0, so the old gain-alone filter dropped every bus). A pickup's marginal gain reruns only the bus seating pass (drivers are fixed), so the real-data optimizer stays ~1.7 s ($10M) and ~9 s ($30M, server planner warm-up). Best $10M plan on real data: 3 shelters + bus pickup at cell 5468, score 76.3.
- ProtectionSource gains optional `via` (the bus pickup no-car shelter riders board). CoverState adds routes, reach, busReach, carLeft; shelterOf is now indexed [part * n + i].
- Storm: riders walk from home to the nearest pickup in reach (Residents.via, board time) and ride to the shelter the engine seated them in; drivers go to their engine-assigned shelter; road-protected blocks stay home. Pickups are no longer halo destinations.
- Planner: a bus spot is valued on top of the best plan's shelters ("takes about N people with no car to the best plan's shelters").
- Known balance point: no-car weight is ~4% of flood weight on the real data (2,000 of 47,813), so buses add little; tune NO_CAR_HH_WEIGHT if buses should matter more.

- 3D shelters (F1): OpenFreeMap's building features are height groups (one MultiPolygon holds many buildings) and their ids are not OSM ids, so a single site's building cannot be colored inside `buildings-3d`. `site-buildings-3d` extrudes the site footprint (site_buildings.json) instead, colored data-driven by `floods` (palette site3d / site3dFloods; both the night building color in the storm, so sites stay hidden there). Its height is the tile building's render_height under it (read at runtime once per site, feature-state `height`) + 0.8 m, and the footprint is pushed out ~0.8 m, so its walls and roof cover the tile building without z-fighting. Unmatched sites keep the deck.gl square (depthCompare always, above the 3D layer).
- Bus pickup demand report (user request: player data for real planners). GET /api/planner/bus-demand?mode=flood&days=&minPlayers=&format=json|csv|geojson. Bus pickups from every play are grouped into H3 resolution 8 areas and counted by distinct players (plays.player_id). Areas with fewer than 5 players are hidden (minPlayers can go down to 3, never lower). Each area carries households with no car and people at flood risk (Census cells, floodRiskShare) and the nearest existing bus stop; a gap is no stop within 400 m (a five-minute walk) of the pick-weighted center. Gaps rank first, then players, then no-car households at risk. Types in shared/src/demand.ts.
- Existing stops: python -m pipeline.transit (stdlib only) writes app/public/data/transit_stops.json from the feeds linked on goraleigh.org/developer-resources: GoRaleigh (Trillium "capital-area-transit", published 2024-01-26, ended 2024-03-31; no newer static GoRaleigh feed is linked there) and GoTriangle (current). 1,445 + 134 stops in the study box (sites.json extent + 0.02 deg). The report states when a feed has expired. Also seeded into Tiger as transit_stops.
- Solo games are now saved: when results show, the app POSTs the plan to /api/plays with an anonymous per-browser id (localStorage, random UUID, no name), fail-soft. Rooms were already saved by the server.
- /planner shows the report (summary, counts, ranked areas, CSV and GeoJSON downloads, method and data dates) and the areas on the map: a gap is a --signal hexagon with a thick ink edge, an area with a stop is a hollow --safe hexagon, both with the player count. Refreshes every 15 s. MapScreen takes optional extraLayers.
- Existing shelters (user decision): registered evacuation shelters from the FEMA National Shelter System "Shelter Locations" layer (American Red Cross; evacuation_capacity > 0) count as protection before any plan. 12 in the study area, 4,998 seats, none in a flood zone. npm run shelters writes existing_shelters.json with catchments computed in Node over roads_graph.json the same way as pipeline/flood.py cover_one (nearest node, reversed arcs, 900 s, flooded graph drops steps <= 3); mean Jaccard 0.999 against the pipeline on 30 sites. NC OneMap "Potential Emergency Shelters" (104, unvetted candidates) are not used.
- Score with a baseline: ScoreResult.baseline = what existing shelters protect with no plan. score and bestPossible = share of the remaining gap (atRiskWeighted - baseline) the plan closes. protectedPeople/strandedPeople stay totals (existing shelters included), so the storm counters and timeline are unchanged. HUD: "N covered of M at risk" uses the gap; the results card says what existing shelters took.
- Seat allocation: a cell that fills one shelter now sends the rest of its people on to its next nearest shelter with seats (supersedes "no split across shelters"; with small existing shelters the old rule stranded the remainder even when a new shelter had room). protectorOf returns one source per seat; CoverState.seats lists them; shelterOf holds the nearest slot (Int32Array).
- Bus pickups: Placement.stopId puts a pickup at an existing GTFS stop for BUS_STOP_ACTIVATE_COST ($0.5M, placementCost()). New pickups ($1M) only on idx.busOk cells (within the walking ring of at-risk no-car residents); planProblems rejects others. The optimizer adds one stop activation per bus cell and drops new pickups in cells that have a stop.
- Optimizer speed with the baseline: pickups are evaluated in order of an upper bound (new no-car weight they let board) and skipped once the bound cannot beat the round's best; seats use slot-indexed typed arrays and stop early when every shelter is full; route lists merge instead of re-sorting. Real data: $10M 1.3 s, $30M 3.8 s. Best $10M plan: 3 shelters + 2 pickups at existing GoRaleigh stops, 78.9 of 100.
- Planning UI (user request, less clutter): candidate shelter sites show only while a shelter is armed, and only sites that stay dry. Bus pickup armed: a yellow tint on bus cells and existing stops there (sized by zoom); taps snap to a stop within ~20 px, else the cell if it is a bus cell. Existing shelters always show (green house, ink edge, name and seats from z12). Bus -> shelter lines (--safe on an ink casing) from protectorOf().via, for the plan and for the hover preview. The Facilities toggle is now hospitals only. Free placement order (user decision); the status line explains a bus with no seats in reach.
- Bus seat reserve (user decision, after playtest): every shelter keeps BUS_SEAT_SHARE = 10% of its seats for bus riders. Drivers fill the other 90% nearest first; buses fill the reserve, most vulnerable riders first (weight per person, then drive time). Unused reserve stays empty. Before, drivers filled every 10,000-seat shelter at once and a bus next to it added nothing. Riders by vulnerability keep "adding a piece never lowers the score" (nearest-first riders broke it in the test by 0.08); 5,000 extra random trials found no violation. Existing shelters keep 10% too: baseline is now 4,498 people, 33,041 still at risk. Best $10M plan: 3 shelters + 2 existing-stop pickups, 75.1.
